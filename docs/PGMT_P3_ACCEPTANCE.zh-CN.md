# PGMT P3 总验收

日期：2026-10-14。**结论：部分通过，P3 尚未全部完成。** P3.1–P3.4 的实现、数值和有限训练链路通过；P3.5 头/胸真实碰撞链路已补验通过，但存在短冲击采样限制，动作接触冲突统计仍待完成；P3.6 尚缺充分的分地形/难度性能统计。recovery pool、recovery upward velocity 和恢复课程按用户要求暂缓，不作为本轮缺口。

本次核对现有计划、生产配置、源码、实际 USD 和独立验收材料，执行当前配置的联合回归及有限训练/恢复。没有修改训练程序、地形或动作资产；指定 Stage1/P2 源 checkpoint 保持不变。已有用户修改（包括 `docs/USER_READ.md`）保留。汇总见 [p3_acceptance.json](../logs/pgmt_p3_acceptance_20261014/p3_acceptance.json)。

## 2. 本次新增证据

**600 项 CPU/CUDA 回归通过，无失败或跳过。** 范围包括接触状态、T1–T6、参考标签、三项容差、终止计时、课程、奖励缓存、配置、三头/四头迁移、PPO、checkpoint 与感知融合；不是整个仓库所有测试。见 [cpu_cuda_tests.txt](../logs/pgmt_p3_acceptance_20261014/cpu_cuda_tests.txt)。

原生训练在 RTX 5090 `cuda:1`、160 环境、完整 862 个动作、v6 地形上运行；正式奖励、感知、容差和终止配置均启用，没有替换成测试奖励。

| 运行目录（`logs/pgmt_p3_acceptance_20261014/`） | 过程 | 结果 |
| --- | --- | --- |
| `stage1_160_01` | 从指定 `model_15000.pt` 迁移，更新 3 次 | next iteration=3，72 控制步，10 次 done |
| `resume_160_01` | 新进程严格恢复，再更新 2 次 | next iteration=5，48 控制步，1 次 done |
| `restore_160_01` | 再次新进程恢复，0 次更新 | 模型、归一化、Adam、LR、iteration、课程、sampler/概率、训练契约及累计训练计数精确一致 |
| `p2_160_01` | 从已有 P2 三头 checkpoint 显式迁移，0 次更新 | 旧参数和感知保留，旧 value 行映射至 0/1/3，新 terrain 行为零 |

合计 **120 个控制步 ×160 环境＝19,200 transitions**、11 次自然失败；四组和与标量奖励最大误差 **4.7684×10⁻⁷**，terrain 非零奖励样本 **19,067**。四个价值头均有非零梯度和参数更新，selector、patch encoder、IFM、actor 也更新。保存文件独立复核通过，见 [有限训练报告](../logs/pgmt_p3_acceptance_20261014/acceptance_report.json)。所有保存的训练契约均确认双腕 EE 集合、四项 `duration_s=0.2` 和 10 s 回合。

该轮配置的验收权重为 [restore_160_01/final.pt](../logs/pgmt_p3_acceptance_20261014/restore_160_01/final.pt)，仅训练 5 次更新。后续 P4 将 PhysX 设置等纳入训练契约，当前入口续训应使用 [P4 执行记录](PGMT_P4_EXECUTION.zh-CN.md) 对应的新 checkpoint，不能把本轮或旧终止/奖励配置的 checkpoint 当作同配置严格续训。每次恢复都会重新初始化物理回合和终止计时，不声称轨迹逐步重放。

此次没有重复所有独立几何探针；引用最近通过的 [0.2 s 终止验收](../logs/pgmt_termination_delay/isaac_01/training_status.json)：5 环境、53 控制步、五类十级，四项分别在第 10 个实际控制步触发，11 次 done 对应 11 次 sampler outcome，reset 清零；三项截断不等待。T1–T6 的原生物理正例分别保留于各专项文档。

首轮 approximate KL 为 **0.158**、clip fraction 为 **0.536**，adaptive LR 降至 `1e−7`；后四次 KL 为 `0.00648 / 0.02159 / 0.01046 / 0.01579`，最终 LR 为 `1.1391e−6`。这些数据说明更新链路数值有限，不能据五次更新认定收敛或超参数合适；本次没有调整 PPO。

## 3. 尚未闭合的两项

### P3.5：动态碰撞与必要接触审计

本次通过 USD 实例代理遍历核对了实际训练资产：**30 个刚体、29 个碰撞体**。`head_link` 的结构节点和视觉节点都是非刚体 Xform；躯干所属四个 capsule 包含局部高度约 0.415 m 的顶部碰撞体。impact 按名称定位 `torso_link`，没有重复增加 head 刚体。完整碰撞归属见 [body_set_audit.json](../logs/pgmt_p3_acceptance_20261014/body_set_audit.json)。普通 `stage.Traverse()` 会遗漏实例化碰撞体，本次使用 `Usd.TraverseInstanceProxies()` 展开后核验。

后续补验（同日）：[身体碰撞到奖励验收](PGMT_BODY_CONTACT_AUDIT.zh-CN.md) 已完成 5 环境、44 控制步；真实 GPU 接触点、指定障碍物合力、生产传感器、两项惩罚及四组归集一致。头部和胸部各 1/2 m/s，空中/双脚负例、终止步缓存及下一物理步无重复计罚通过。原生结果见 `logs/pgmt_body_contacts/isaac_06/`。原始总验收 JSON 保留当时状态，以本补充和专项报告为当前进度。

当前状态：

1. **碰撞归属及计算链路已通过**，没有按 head/torso 重复计数。但物理频率 200 Hz，奖励只取每个 50 Hz 控制步的末子步；胸部 2 m/s 物理峰值约 5115 N，奖励样本最大约 253 N。短冲击采样风险已确认，聚合方式尚未修改，不能概括为冲击完全无漏采。
2. 对爬行等普通动作统计膝/手必要接触与 `undesired_contacts` 的冲突。当前集合为除双脚外的 28 个刚体，包含膝和双腕，未使用动作条件掩码。是否需要调整应根据统计决定；本次保留现有行为。

当前资产/动作顺序中 pelvis 确实在完整 body 数组第 0 位；基础加速度公式仍使用索引 0，更换资产时需继续验证，不能把本次资产核对推广到任意机器人。

### P3.6：分地形与难度的策略表现

当前短训出生等级为 L0/L1，未产生完整动作升级样本，不能替代五类十级的策略完成率验证。几何探针覆盖 50 区域也不代表策略能通过这些区域。

仍需在固定、兼容的动作/地形评测清单上运行足够的完整片段，按 family/level 输出：完成/失败/截断比例、终止项及连续超限时长、三项原始/放宽误差、四组及分项回报、接触匹配和事件率；对楼梯/箱体边缘、爬行动作单独回放异常样本。躯干单点地面高度与真实支撑面不一致的持续误差，不能仅靠 0.2 s 容忍消除。

此项是本轮 P3 的策略适配验收；P4 的正式长训和论文式连续 30 s benchmark 另行执行，不把五次 PPO 更新解释为任何一项性能验收完成。
